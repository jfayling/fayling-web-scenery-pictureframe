# Contributing

Thanks for your interest in the scenery picture frame. Bug reports, screenshots of rendering problems, new regions, and performance work are all welcome.

## Ground rules

- **No runtime dependencies.** The app is plain JavaScript and WGSL with no framework or bundler at runtime. `esbuild` is only used at build time to minify the bundle.
- **Standalone must keep working.** `scenery.html` and `scenery.min.html` have to open straight from disk (`file://`) with no server and no network requests for terrain.
- **No per-frame garbage.** The renderer preallocates its typed arrays and GPU descriptors. Please keep allocations out of the frame loop.
- **Measure before you claim.** If a change affects performance, include before/after GPU times from the HUD (`showInfo=true`), the GPU you used, and the resolution.

## Getting started

```
git clone https://github.com/jfayling/fayling-web-scenery-pictureframe.git
cd fayling-web-scenery-pictureframe
npm ci
npm start            # http://localhost:8081/
```

`npm start` serves the module sources from `js/`, so edits show up on reload. You need a browser with WebGPU; see [browser support](docs/browser-support.md).

## Before you open a pull request

1. Run `npm run build`. This regenerates `scenery.html` and `scenery.min.html`. **Commit both bundles.** CI fails if they don't match the sources.
2. Run `npm test`. This runs the camera route and lunar terrain decoding tests.
3. Run `npm run site`. This assembles the GitHub Pages site in `_site/` and checks that every asset path resolves.
4. On Windows with a GPU, run `node tools/check-scenes.mjs`. It renders every lunar region and both offline bundles in headless Chrome and checks for shader and runtime errors.
5. For visual changes, attach before/after screenshots. `tools/shot.ps1` renders a frame in headless Chrome:

   ```
   powershell -ExecutionPolicy Bypass -File tools/shot.ps1 -Name pnw.png -Query "scene=pnw"
   ```

## Code conventions

- `build.mjs` concatenates every module into one scope, so **top-level names must be unique across files**.
- WGSL lives in template literals under `js/wgsl/`. The minifier strips comments and whitespace from them, so don't rely on either inside shader code.
- Keep comments for constraints the code can't express (units, coordinate frames, GPU layout rules).
- Lunar elevation assets in `js/moon*-data.js` are generated by `tools/prepare-moon.py`. Don't edit them by hand; see [Moon terrain](docs/planet-terrain.md).

## Adding an Earth region

Regions are entries in `SCENES` in `js/scenes.js`. Each one sets the landform, flight altitude and speed, forest and water parameters, and an optional sky. Please include a screenshot of the new region and a sentence describing the real landscape it's based on.
